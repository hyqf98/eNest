# 旧插件数据导入兼容边界

更新：2026-10-24，适用于宿主 0.2.3。这两份固定来源适配器是迁移兼容层，不是插件业务服务；不得为追求源码中没有业务名称而删除旧用户的升级入口。

| 适配器 | 宿主允许处理的范围 | 必须留给插件的内容 |
| --- | --- | --- |
| `src/main/clipboard/legacyClipboardMigration.ts` | 仅 `com.github.eNest.clipboard` 可读取固定 `clipboard-history-v1` 来源；有界传送原文档与 PNG，校验来源身份和配额，写幂等提交标记 | 历史格式解释、去重、保留、索引、查询、置顶及当前历史写入 |
| `src/main/timer/legacyTimerMigration.ts` | 启动时检查固定 `focus-timers-v1` 容器，按原所有者分块写入插件私有存储，事务性记录一次性迁移 | 番茄阶段、长短休息、自动推进策略、历史/统计及旧 payload 的业务解释 |

## 不变条件

- 不增加可由插件指定的宿主路径，不把这两处兼容接口扩大成任意文件访问 API。
- 原文件和附件保留；迁移提交不等于授权删除用户备份。已写标记不得因卸载插件而清除，避免重装复活旧数据。
- 旧文档变化、大小超限、符号链接、调用者不匹配或迁移失败时拒绝导入并保留来源，不宣称部分写入已经成功。
- 兼容适配不能成为新业务 fallback。当前插件必须在自己的 backend 或沙箱后台解释与管理数据。

## 退场条件

目前仍支持旧版本直接升级，因此本轮保留这两份适配器。只有正式决定不再支持含上述数据布局的旧版本直接升级，并提供可用的显式导入路径或经用户确认的迁移安排后，才可移除宿主适配。

删除前还须核对插件发布版本、来源/所有者校验、成功标记、失败保留和重复导入防护；不得仅凭某台开发机没有旧数据，或新安装验收通过，就宣布可删除。保留适配器不代表本轮验证过所有真实用户历史数据。
