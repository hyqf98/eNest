# 精选轮播逐帧回归

2026-10-15，Chromium 155.0.8059.79，headless，1440 × 1000，动画档位 medium，实际发布目录 35 个插件。

运行：`ENEST_CAROUSEL_MOTION=1 node --test src/renderer/components/useProductCarousel.browser.test.mjs`

最终结果：三个子场景全部通过（Node 连同父测试统计为 4/4）。原始采样及断言摘要见 `frame-checks.json`。

| 检查 | 结果 |
| --- | --- |
| 邻项切换与中途反向 | 30 / 44 个采样帧；reveal 与实际水平位置最大误差 0.000494；真实点击事件前后位置差 0 px |
| 正向 / 反向首尾衔接 | 29 / 29 个采样帧；各只有一次预期的 clone 归一跳转 |
| 真实鼠标拖拽 | 49 个采样帧；reveal 与实际水平位置最大误差 0.018935 |
| 离屏暂停、回屏恢复 | 离屏等待 400 ms 后位置保持 2466 px；回屏完成至 index 2 |
| 恢复后的自动播放 | 等待真实的 6.5 秒周期后进入 index 3 |
| 同卡片排版不重叠 | 共 226 个采样帧，没有同一 slide 的 copy 与 peek 同时 opacity > 0.1 的样本 |

这些检查证明所测场景的位置、透明度、衔接及暂停状态连续，不代表桌面 Electron 的帧率结果。原生窗口失焦测试由主任务单独验证。

初次截图发现线性互补淡入淡出会让同一卡片的 peek 与完整文案形成双标题、双图标。修复后保留 hook 的位置 reveal（0–1），CSS 改为 peek 在 reveal 0–0.2 淡出，完整文案在 0.2–0.7 淡入，离场前 30% 仍显示完整文案。逐帧断言分别校验位置和显隐曲线，曲线 opacity 最大误差约为 1.11e-16，同时禁止同卡片两种排版一起可读。

更新的 `mid-transition.png` 是实际动画中途截图，已目视确认进入的“数据库”只有一套标题及图标，原先的交叉重影已消除。反向点击位置在真实 click 事件前后取样，避免将 Playwright 点击准备时间里的正常动画位移误判为跳转。
