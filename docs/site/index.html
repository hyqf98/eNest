What it actually is

不是启动器，是可拆装的桌面底座

安装、隔离、主题、数据、调试链路一次配齐。下面每一块都对应源码里的真实能力。

多 Tab · 真进程隔离

每个插件使用独立的 WebContentsView 与 persist:plugin-{id} session。 Cookie、localStorage、缓存互不串扰；关 Tab 直接 close()，无 LRU 保活。

  • 崩溃与内存占用不互相拖累
  • 切换 Tab 只改可见性，不销毁不可见页
  • 关窗口统一 destroyAll()

拖拽安装 · 本地热加载

市场一键安装，或开发者控制台「加载本地目录」。最多 3 个并行安装队列； 改完源码热重载，DevTools 一键打开。权限不足会返回明确错误码，而不是静默失败。

  • webUtils.getPathForFile 解析拖入路径
  • enest://plugin/{id} 协议限制在插件根目录
  • 卸载可按版本策略清理数据
拖入 .enestplugin 或本地目录

主题 Token · 插件跟着变

浅色 / 深色 / 跟随系统；颜色、圆角等 Token 可调，支持背景图与视频。 插件声明 themeAware 后，加载时注入 CSS 变量，切换时推送事件——不用嵌壳子 DOM。

  • chrome：default / minimal / none
  • 透明背景可透出壳子壁纸
  • 主题包可经 enest.theme.register 动态注册

Manifest first

清单驱动 · 权限可控

参考 uTools 的插件模型：清单 + Web 入口 + 受控 API。 eNest 用 Electron 原生多 View 做到真正的进程隔离与多 Tab。

  • plugin.json 字段完整校验
  • 生命周期：打开 → 切换 → 重载 → 关闭销毁
  • UI 标准：chrome / themeAware / 透明背景
  • 权限键与 zapi API 一一对照
插件文档 zapi API 
// plugin.json 最小示例
{
  "id": "com.example.hello",
  "name": "Hello eNest",
  "version": "1.0.0",
  "main": "index.html",
  "permissions": [
    "clipboard",
    "notify"
  ],
  "ui": {
    "chrome": "default",
    "themeAware": true
  }
}
