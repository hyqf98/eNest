# 生命周期与资源责任

宿主负责创建、挂载、隐藏、休眠和销毁原生 WebContentsView；插件负责业务状态与页面内资源。回首页或设置时必须隐藏插件原生层，renderer 的高 z-index 不能覆盖它。

| 场景 | 行为 |
|---|---|
| 第一次打开 | 创建独立运行代次，加载入口，ready 后进入 |
| 同插件并发打开 | 合并开启操作，不重复创建实例 |
| Quick / 主窗 / 独立窗 / 面板迁移 | 沿用同一 View、文档和业务状态；只有展示模式改变时才发送 mode 变化 |
| 切换 Tab / 主窗或独立窗隐藏、最小化 | 旧实例进入后台，按可见性与活动租约安排闲时回收 |
| Quick 已进入插件后自动隐藏 | 只改变可见性，保留当前逻辑会话、View 与接管输入，豁免普通闲时/LRU 回收 |
| Quick 的 Esc / 返回 / 显式停止 | 结束逻辑会话并清理已交付输入；返回列表后的后台实例才恢复普通回收策略，停止后不自动重开 |
| 应用启动恢复普通 Tab / 独立窗 | 先恢复冷占位和窗口历史，用户明确打开后才启动插件；不是批量重放上次业务请求 |
| 应用启动恢复自由面板 | 先恢复面板与组件占位，再以最多 2 个并发挂载插件；失败保留重试入口 |
| 后台空闲三分钟 | 尝试 beforeSuspend 保存确认后释放实例 |
| 超过六个驻留实例 | 对合适的后台实例执行 LRU 回收；不是六个逻辑 Tab 上限 |
| 活跃任务 lease | 保护仍在执行的受控任务，可能暂时超过软上限 |
| 关闭 / 重载 / 崩溃 | 终止旧代次，在途回调不能写入新实例 |
| 崩溃后的打开 | 保留错误 Tab 或组件条，用户显式重试；不自动循环重启 |
| 停用 / 卸载 | 停止相关后台任务与贡献；卸载同时清理私有数据，但保留防止旧数据再次导入的宿主迁移标记 |

开发注册默认不参加普通闲时休眠/LRU，以保持 HMR。开发者可停止实例或使用“退出即杀”。不要靠永久计时器或声明无关权限阻止回收。

普通页面可用 `enest.runtime.acquireActivity(reason?)` 临时保护在途工作，并在 `finally` 调用 `releaseActivity(token)`。显式租约每运行实例最多128份、全局4096份；可选说明必须为长度不超过160的字符串。租约只影响闲时/LRU回收，不拦截显式关闭、撤权或退出，且只能由原运行代次释放。详见[API 活动租约](api.md#runtime-活动租约)。

## 身份与挂载位置

插件 ID 代表数据与声明的所有者，不代表一个永不变化的运行实例。宿主还区分包的构建修订、页面运行代次与逻辑会话。普通视图迁移保留实例身份；重载、休眠唤醒、崩溃重开和升级会创建新运行身份。插件不能持久化并复用旧文件句柄、网络连接 ID、活动租约或临时启动句柄。

`PluginLaunchMode` 有 `quick`、`shell`、`panel` 三种布局，原生挂载位置则包括 Quick、主窗、独立窗口和自由面板。两者分离：独立窗口保留原布局；面板只接收显式声明 panel 的插件，不提供默认工作台兼容视图。启动请求目标 `PluginLaunchTarget` 只有 quick/shell；`default` 仅在请求布局未适配时使用。统一启动器只有在最终回退 panel 时才在主窗呈现该布局，不自动创建面板；默认 panel 不会覆盖已适配的 quick/shell 请求。

插件通过 `getLaunchMode/onModeChange` 获取布局，通过实际内容区与 `ResizeObserver` 获取尺寸，不自己操作原生父窗口。只有布局值改变才触发模式事件，不能依赖每次迁移都收到回调或重放 onEnter。可见独立窗口不会仅因失焦就休眠；隐藏或最小化后按活动与空闲策略处理。面板组件作为常驻呈现，不参加普通闲时/LRU 回收，宿主对面板 chrome 和其插件 View 关闭后台节流，迁出面板后恢复普通策略；实际拖动、缩放或菜单期间临时隐藏原生业务视图，也不等于销毁组件，结束后自动恢复真实内容。该策略不能代替目标平台失焦/遮挡后的持续绘制验收，也不能代替插件自身正确管理页面资源。

关闭独立窗口会关闭插件；移回主窗只移交 View，不关闭实例。自由面板的关闭、移回主窗与关闭功能开关也有不同的布局语义，见[自由面板](panels.md)。普通 Quick 临时会话不自动加入启动恢复历史。正在原生选择器或确认框中交互时，宿主会限制容器迁移，避免确认结果交给另一个页面。

已有面板组件或独立窗口从普通 Quick 搜索（未指定显式目标）或宿主普通打开（`ShellOpenPlugin`）再次打开时原地聚焦，新载荷仍按 onEnter 处理。Workspace 目录、详情和首页搜索显式请求 shell，走统一启动器的布局回退与目标选择，可能迁移已有实例；设置入口、快捷键目标或拖动/固定动作也可以迁移。`ShellOpenPlugin` 新开实例时则保留主窗位置，回退 quick 布局也不转入 Quick。入口策略不能仅按“位于主窗”归类，完整决策见[UI 集成标准](ui-standard.md#三种布局与挂载位置)；迁移继续复用原实例和业务状态。

## 页面代码

使用 `onEnter` 处理启动参数，`onOut` 暂停动画和页面轮询，`onModeChange` 切换呈现布局。业务 store、编辑器 model、后台计划控制器在三布局之外共用，切换布局不重新初始化它们。订阅返回的取消函数应在不再需要时调用。模块状态只在当前文档内存在，不能当作持久数据。

`onBeforeClose` / `onBeforeSuspend` 中保存必要草稿并返回 Promise。无异步工作时 preload 通过 microtask 确认，不使用固定 50ms 延迟。关闭有期限，挂起的回调不能永久阻止用户关闭；普通休眠保存失败或未获确认时延后重试，不把未确认草稿静默当作成功快照。不要把关闭回调用作唯一数据保存时机，也不要依赖浏览器 `beforeunload` 的异步工作。

数据保存双保险（详见 [API — 壳通知](api.md#壳通知shellnotice)）：编辑时 `enest.setDirty(true)`、落盘后置 `false`，壳子更新重启前据此检测未保存数据；`enest.onSaveRequested(cb)` 在壳一键保存（`save.requested` 通知）时触发，回调返回 Promise，settle 后壳才继续（超时兜底放行）。保存必须幂等——`save.requested`、`beforeClose`、`beforeSuspend` 可能对同一数据先后触发。

`storage.session` 用于同一逻辑会话的临时状态和休眠恢复；重载、关闭、应用重启是否保留由会话身份及构建修订控制，不能替代持久存储。需要重启保留的数据使用 `enest.storage`（基础能力，无需声明或授权）；生产包更新不恢复旧构建的不兼容检查点。

`storage.set/remove` 只确认进入宿主写队列。检查点需先等待写入，再 `await enest.storage.flush()`，或直接 `await enest.storage.commit(operations)` 取得同插件 KV 的显式提交回执；这不包含图片/文件事务。`@enest/plugin-kit` 会在关闭和休眠时等待已排队写入，并在宿主支持时 flush；插件自己的防抖快照仍须主动提交且返回 Promise。`kit.flush()` 在旧宿主不支持持久回执时明确失败，不能伪造落盘成功。详见[存储标准](storage.md)。

## 后台不是前台保活

| 机制 | 关闭前台后的行为 |
|---|---|
| 页面定时器、Worker、前台订阅 | 属于当前文档；隐藏时暂停不必要工作，销毁时释放，不保证持续运行 |
| `runtime.acquireActivity` | 保护当前实例的真实在途任务，不是永久后台运行授权 |
| `background.entry` 沙箱事件后台 | 合格的持久授权与启用事件可继续工作；后台实例可空闲回收，后续从私有文档重建 |
| `backend.entry` Node 后端 | 绑定当前插件实例；关闭或撤销完整 Node 信任时按通用关闭协议回收，不承诺脱离实例常驻 |
| `deadlineTasks` | 通用计划可跨 Tab 关闭和休眠；应用退出/重启后恢复为暂停，不要求 renderer 保活 |
| `auxiliary` / 捕获 / 未完成输出流 | 绑定前台实例；正常关闭仅有有界收尾期，撤权或强制销毁时释放 |

沙箱后台不得因设置刷新或 Quick 查询绕过持久授权、禁用或手动停止状态；事件开关也不等于敏感权限。它没有普通 `enest` 或 Node。其业务文档、历史索引与事件处理必须自行保证幂等，详见[沙箱后台 API](api.md#background-插件私有沙箱后台)与[权限说明](permissions.md)。

宿主在关闭时先使旧运行域停止接收普通新任务，再进行有界保存和清理。异步操作在等待授权、磁盘或后端结果后复核原运行身份；超时不能只丢弃 Promise 而遗留持续工作的资源。已经提交的文件或 KV 不因晚到的关闭而自动回滚，成功回执丢失时须重新核对。插件的 `finally` 同样要释放自己的订阅、对象 URL、Worker 和活动租约，避免将清理工作寄托于页面最后一条事件。

资源释放失败或超时不视为关闭成功：宿主保留旧代次与未完成清理项，显式重试只重试失败项，并复用仍在执行的释放任务。即使页面已销毁，尚未确认退出的宿主创建进程仍属于原次清理；面板的重试不会转而关闭同 ID 后来新建的实例。在旧资源清理完成前阻止同插件创建重叠实例；关闭多个面板组件及应用退出会等待全部关闭尝试，再汇总失败。扫描注册表只发现安装身份和同名提示，不按显示名称删除另一个插件；替换/卸载必须经过统一安装锁与关闭链路。

## 宿主预算

session 每插件 8MiB、全局 64MiB；静态资源缓存 32MiB，大文件流式读取。KV 单值 512KiB、每插件最多 1000 键，待提交写入每插件 8MiB、全局 64MiB，键不超过 1024 个 UTF-8 字节。超过预算返回错误，已经接受的写入仍保留等待重试。

代码缓存使用 Chromium/V8 实现，更新或显式重新加载失效对应修订。缓存文件存在不等于已经测得编译耗时下降，性能报告需写明实际测量口径。

普通插件页面在 Chromium sandbox 中运行。DSH 的专属独立运行时是另一个执行边界，本页不承诺其进程具备页面沙箱隔离。
