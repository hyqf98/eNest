# 开发加载与热更新

开发注册不会复制或安装插件。壳启动时恢复源码登记，首次实际运行插件时才连接或启动它的开发服务。手工加载源码会立即准备并打开插件；启动调试和重载已打开插件也会立即准备运行环境。

## 启动恢复与按需服务

重启壳时，只校验本地 manifest、解析开发命令、恢复插件列表、声明式贡献和源码监听，不探测开发服务、不启动进程；普通业务入口不会因服务离线而等待或提前选用构建产物。主题受限页面的本地资源根另行解析，规则见下方「主题工作区的开发刷新」。当前主题所需的贡献同步完成后，开屏和首页预热继续进行；普通业务插件的开发服务就绪不作为开屏条件。

首次从首页、Quick、快捷键、面板或 MCP 实际运行插件时，宿主通过统一打开入口准备服务。同一插件的并发请求共用一次准备，不同插件新启动服务的并发上限为 2；复用已在线服务不占启动名额。已开启面板恢复等真实运行需求仍可触发对应服务，恢复逻辑 Tab 本身不会启动服务。

服务未运行时，壳按插件 `package.json` 解析出的命令自动拉起；端口被其它项目占用时尝试空闲端口。宿主启动的进程由宿主管理，禁用、忘记开发注册或退出时取消待处理任务并回收；开发者手工启动的外部服务只复用，不由宿主关闭。失败仅影响对应插件，登记保留，可再次尝试；日志面板显示服务输出。

终端中的 `[startup]` 记录主进程相对 `app-ready` 的单调计时；开发态壳 DevTools 中的 `[startup:renderer]` 和 `enest:startup:*` Performance 标记则相对该页面导航开始计时。两者使用不同起点，不能直接相减。`shell-window-created` 只表示窗口已创建，`shell-window-shown` 才表示原生窗口触发显示；它们与 renderer 的 `splash-mounted`、`splash-done` 分开记录，原生显示事件也不等于像素已经绘制完成。

## 启动命令解析（壳子零预设）

壳子不写死任何工具链。启动/构建命令按以下优先级从插件源码根的 `package.json` 解析，各维度独立回退：

| 维度 | 解析链 | 缺省 |
| --- | --- | --- |
| dev 服务 URL | `enest.dev.url` → `plugin.json development.main` | 无（纯静态源码预览） |
| 启动命令 | `enest.dev.command`（原始命令逃生舱）→ `enest.dev.manager` + `enest.dev.script` → 锁文件检测包管理器 + `scripts.dev` → `scripts.start` | npm |
| 端口漂移参数 | `enest.dev.portArgs` 模板（`{port}` 占位） | `["--","--port={port}"]` |
| 构建命令 | `enest.build.command` / `manager` + `script` → 锁文件检测 + `scripts.build` → `scripts.pack` | npm |
| 产物目录 | `enest.output` | `dist` |

- **包管理器**：优先看 `enest.dev.manager` 显式声明；否则按锁文件检测（插件目录向上最多 4 级找 `pnpm-lock.yaml`→pnpm、`yarn.lock`→yarn、`bun.lockb|bun.lock`→bun、`package-lock.json`→npm，兼容 workspace 根持锁），都找不到按 npm。npm / yarn / pnpm / bun 四种统一走 `<manager> run <script>`。
- **原始命令逃生舱**：非 node 工具链（如 `deno task dev`、`make dev`）写 `enest.dev.command`，整行交给系统 shell 执行；命令里的 `{port}` 占位符在端口漂移时替换为实际端口。
- **环境变量**：实际端口始终注入 `ENEST_DEV_PORT`，任意工具链的启动脚本都可读取。
- **零配置即可用**：不写 `enest` 段时，`development.main` + `scripts.dev`（或 `scripts.start`）+ 锁文件检测就是完整声明；官方插件全部如此工作。
- **纯静态 HTML 插件**：没有 `package.json` 或没有可用脚本时不拉服务，直接源码静态预览 + 文件变更自动重载。

```jsonc
// package.json（可选扩展，全部字段可省略）
{
  "scripts": { "dev": "vite", "build": "vite build" },
  "enest": {
    "dev": {
      "url": "http://127.0.0.1:5173/",
      "manager": "pnpm",
      "script": "dev",
      "portArgs": ["--port", "{port}"],
      "command": "deno task dev --port {port}"
    },
    "build": { "script": "build" },
    "output": "dist"
  }
}
```

字段 Schema 见[官方 package 扩展 Schema](https://github.com/hyqf98/eNest_plugin/blob/main/docs/enest-package.schema.json)。畸形或类型不符的 `enest` 字段会被静默忽略，不会阻断加载。

## 自动识别，无模式切换

开发者控制台只有开发模式：壳后台自动识别插件源码形态，列表区分「待启动 · Vite / 对应框架」「开发服务 · Vite / 对应框架」「静态 HTML」「构建产物」，没有 dev/prod 切换，也没有「重新构建」按钮。

- **有开发服务声明**（`development.main` 或 `enest.dev.url`）：启动恢复后先显示「待启动」。实际运行时优先连接已在运行且身份匹配的服务；未运行时按解析出的启动命令自动拉起并等待就绪，走框架 HMR。调试快捷键（仅 dev 插件与壳窗口响应）：插件页内 **F12 / ⌘⌥I / Ctrl+Shift+I** 开关 DevTools，**⌘R / Ctrl+R** 重载插件（开发服务掉线时重载会自动重新拉起）。
- **服务无法连接或自动启动失败，但已有匹配的构建产物**：按 `enest.output`（缺省 `dist`）产物目录预览，标签显示「构建产物」。除插件 ID 和版本相同外，产物 manifest 必须与源码 manifest 去掉 `development` 后完整一致，避免准备运行入口时替换功能声明或权限。版本或声明不一致时拒绝加载并提示构建命令；需在插件目录重新运行构建脚本（如 `npm run build`）。
- **无服务声明**：源码静态预览（保存后自动重载），标签显示「静态 HTML」。

框架识别只读 `package.json` 的依赖指纹与启动命令内容（如含 `vite` / `next` / `nuxt` / `webpack`），识别结果不落盘。旧的 dev.json 记录里多余的 `mode` / `preview` 字段会被忽略并丢弃，不影响加载。

## Vue、React 与 Vite

1. 在插件目录执行依赖安装（首次）。
2. 壳设置 → 开发者，选择含 `plugin.json` 的源码目录；开发服务未运行也没关系，壳会按解析出的命令自动拉起。
3. 默认读取 `development.main`（或 `enest.dev.url`），端口与启动脚本一致，避免与其它插件开发服务冲突；不要把某个仓库的端口范围当作宿主协议。
4. 加载后立即打开壳内插件页，HMR 由 Vite 处理；纯前端插件无需已有 `dist`。声明 Node 后端的插件必须先构建 `dist/backend`，后端入口不会由 Vite 开发服务器提供。

```json
{
  "development": { "main": "http://127.0.0.1:5173/" }
}
```

开发地址覆盖值保存于开发注册记录，不修改源码。支持明确配置的局域网地址；只放行该 origin 及其 HMR WebSocket。远程服务器需要自行配置监听地址、防火墙和 HMR 主机。不要把 Vite 的 `0.0.0.0` 监听地址填成实际访问地址。

修改 preload 或主进程必须重启壳；普通插件页面的 HMR 不需要重启。后端源码修改后在插件目录重新运行构建命令（如 `npm run build`），再关闭/重载插件实例；已有 utility process 不接受前端 HMR 更新。带后端的完整产物验收见[本机后端](backend.md)。更换服务器地址后重新加载开发注册，旧视图会关闭并创建新的权限边界。

## 原生静态源码

无开发服务声明时，不连接服务器。公开映射固定为：

| 页面 URL | 源码文件 |
|---|---|
| `index.html` | 根 index.html |
| `src/**` | 根 src/** |
| `assets/**` | public/assets/** |

只支持浏览器能直接运行的 HTML、JS、CSS。TS、JSX、Vue 单文件组件和 npm 裸模块导入需要构建工具。`.git`、`.env`、package.json、node_modules 不由源码协议提供。

源码预览模式下壳监听开发注册目录，保存后自动刷新；监听属于开发注册，不依赖普通插件 Tab 是否打开。未运行插件的源码变化只更新登记和贡献，不自动拉起开发服务；运行中的普通插件页继续交给框架 HMR，清单或运行入口变化时才执行必要重载。关闭样式台不会停止当前主题首页的监听；移除开发注册才释放源码监听。移除时宿主取消准备任务并回收该注册拥有的视图、开发服务进程树、文件监听、后台/后端进程与定时任务，注销热键与「打开方式」路由，最后移出注册表并清持久记录；插件数据保留，随时可重新加载同一目录。

### 主题工作区的开发刷新

主题的 Workspace、Quick、chrome 和 settingsPage 使用独立的本地资源根。源码根下已声明的全部受限 HTML 入口齐全时优先使用源码；缺少入口时，才检查 `enest.output`（缺省 `dist`）。产物须通过完整发布包校验，且 ID、版本及 `homePages`、`themePacks` 声明与源码一致，才能作为整组主题页面的资源根。没有匹配产物时保留源码根，由现有页面校验与恢复流程处理。这个过程只读本地文件，不连接 Vite，也不改变普通业务页首次运行时的服务准备规则。

普通插件页有开发服务时由框架 HMR 更新；主题的独立 Workspace 通过隔离的 `enest-home://` 本地资源协议加载。修改 `homes/**`、`src/**`、样式或 `plugin.json` 后，宿主防抖重读清单并等待主题贡献同步，再刷新权威外观快照和当前来源的 Workspace。新页面仍须在隐藏状态完成 ready 与当前路由 ACK，随后替换旧页面；保持当前路由和宿主可见性，加载失败保留上一个可用页面。静态主题源码入口齐全时，无需打包、重装或切换主题；选用产物根时，更新产物后需重新加载源码登记。

监听忽略 `.git`、`node_modules` 和构建产物目录，避免打包触发循环刷新。无效或写入中的清单不会先撤掉当前主题；修正保存后可继续重试。普通 dev 插件仍默认不参加闲时休眠/LRU。停止普通 Tab 仅释放实例，移除开发注册只删除记录、不删除源码。

以上自动更新适用于插件源码。修改 eNest 宿主主进程或 preload 本身仍须重启 `npm run dev` 一次，普通页面 HMR 不能替换正在执行的主进程模块。

## 发布前预览

发行前验证不再依赖模式开关：先在插件目录运行构建命令生成产物。实际运行时，只有开发服务无法连接且未能自动启动，壳才尝试按 `enest.output` 产物目录预览（标签「构建产物」）；单纯重启壳或停止服务不会强制切到产物。要明确验证发布行为，应解包 `.enestplugin` 走正式安装路径，确认资源、图标、README 和截图均不依赖源码树或外部 CDN。

实际打开时，服务器无法连接或自动启动，且无可用产物，才显示加载失败；启动服务器后可重试。不要通过关闭沙箱、放开任意 localhost 端口、加载 file:// 或增加宿主文件监听解决白屏。

日志与 DevTools 针对列表中的指定插件操作。自动测试使用独立 `ENEST_TEST_DATA_ROOT` 与 `ENEST_TEST_USER_DATA`，不污染用户数据。

## 多插件性能诊断

Quick 保留已成功取得的主题配置和原生目录，重复呼出复用这些快照。安装、禁用、入口索引、启动别名、主题和应用目录变化会使对应快照失效；读取失败可在下次呼出重试。多个页面同时刷新应用列表时共用正在进行的扫描，扫描结果未变化时不重新发布目录。缓存不改变打开时的身份、代次和权限校验。

批量安装的解包与文件哈希共用最多 2 个工作线程，其余任务按先后顺序等待，队列最多 128 项，满时明确返回繁忙错误。每项 120 秒执行超时从工作线程创建成功后计算，不包含排队时间；退出会取消等待与执行中的任务，工作线程真实退出后才允许调用方继续清理目录。

设置中的「性能诊断记录」由用户主动开始，默认关闭；每 5 秒保存一个样本，最长 10 分钟，最多 121 个样本 / 4 MiB。停止后可导出 JSON。除进程内存、CPU 差分和实例资源计数外，`samples[].mainEventLoop` 记录主进程事件循环的区间统计：

- `delayMs.p50/p95/max` 是 `monitorEventLoopDelay` 原始直方图从纳秒转换为毫秒的结果，监测分辨率为 20 ms，不减去该分辨率；`sampleCount` 为 0 时延迟为 `null`。
- `eventLoopUtilization` 是该区间事件循环的活跃/空闲毫秒及 0–1 繁忙比例，不是进程 CPU 占用或动画 FPS。
- `sampledAt/intervalMs` 在异步进程采样前记录，不能与进程 CPU 的采样区间混用。停止、退出或采样异常会关闭观察器；异常后未能继续观察的样本为 `null`，旧版 v2 报告可缺省该字段。

首次加载、重复打开、批量导入应分别观察，并保持相同的开发/发布模式与 DevTools 状态。诊断记录帮助定位主进程阻塞和资源变化；它不直接证明 Quick 呼出延迟、动画帧率或内存泄漏。类型检查和构建通过也不能替代目标平台实际运行验收。
