# FAQ

## 开发

**Q：必须用 React/Vue 吗？**
A：不必。可以使用原生 HTML/JavaScript，但开发工程仍须符合[标准目录](structure.md)，包含匹配短名、版本与 `type: "module"` 的 package.json。`main` 固定为 index.html。浏览器可直接执行的源码可静态预览，TS/JSX/Vue 需要构建工具；开发服务离线且存在版本一致的产物时，壳以构建产物目录为运行根。

**Q：必须用 npm 吗？**
A：不必。壳子按插件 `package.json` 解析启动命令：锁文件自动检测 pnpm / yarn / bun / npm，或用 `enest.dev.manager` 显式声明；非 node 工具链写 `enest.dev.command` 原始命令。见[开发加载](debug.md)。

**Q：`window.enest` 和 `window.zapi` 什么关系？**
A：同一对象的两个名字。`zapi` 是保留兼容的 deprecated 历史别名，新代码直接用 `window.enest`，不要依赖尚未发布的移除版本承诺。

**Q：能 `require('electron')` 或调 Node API 吗？**
A：普通插件页面不能，它在 Chromium 沙箱中使用 `enest.*`。需要 Node 时声明 `backend.entry` 并取得独立的 `backend.node` 完整本机信任，在后端使用 Node API；不会让前台获得 Node，也不是任意 Electron 主进程 API 透传。见[本机后端](backend.md)。

**Q：改了 `plugin.json` 权限没生效？**
A：已安装包要重新构建并安装更新；仅改源码不会改变安装包。开发插件通过开发者页刷新注册或源码清单监听重读声明，再重载实例；普通页面 HMR 不代表清单、授权或后端已经更新。新增敏感权限仍需用户授权。

**Q：`id` 能改吗？**
A：安装后尽量不要改。`id` 决定安装路径与 `persist:plugin-{id}`，改了等于新插件，旧数据仍在旧目录。

## 运行

**Q：为什么关掉 Tab 内存就下来了？切走的 Tab 呢？**
A：关闭会先进行有界保存与资源回收，不保证操作系统内存数字立即下降。切走后的普通 Tab 在后台空闲 3 分钟或驻留实例超过 6 个软上限时尝试休眠，保留逻辑会话及已确认快照；活动任务、可见独立窗、面板和开发调试有各自保留条件。重建页面不是恢复 JavaScript 堆，见[生命周期](lifecycle.md)。

**Q：插件崩溃了怎么办？**
A：宿主清理旧运行实例和资源，保留错误 Tab 或面板组件的重试入口，由用户显式重开，不自动循环重启。没有提前持久化的页面内存不能保证恢复。

**Q：多插件数据会串吗？**
A：普通页面的 session、私有存储与 IPC 按真实插件身份隔离，不能通过参数指定另一个所有者。已获完整 Node 信任的后端不属于操作系统文件沙箱；不要把前台存储隔离推广为任意 Node 代码的安全保证。

**Q：插件能读其它插件或壳子 DOM 吗？**
A：不能跨 View 访问。资源协议只提供自己的声明入口和许可公开资源，拒绝路径穿越；后端、runtime、密钥与其它插件的私有资源不会因位于磁盘根目录内就对页面公开。

**Q：`storage.set()` 成功后可以显示“已保存”吗？**
A：它只确认进入有界写队列。需要持久提交回执时使用 `storage.commit()`，或先等待 set 再调用 `storage.flush()`。图片和完成文件各有独立的提交与清理接口，`storage.clear()` 不会清空这些资源，见[存储标准](storage.md)。

## 发布

**Q：怎么打包插件？**
A：规范扩展名为 `.enestplugin`（zip，内含 `plugin.json`），可直接拖入壳子安装。

**Q：要提交 node_modules 吗？**
A：不要。仓库提交源码、资源和依赖锁文件；发布包只放经校验的 dist 内容，不提交构建产物。

**Q：市场审核 / 权限展示？**
A：市场使用 registry 与真实发布包，开发 checkout 的预览不是正式包的市场兜底。插件调用已声明但未授权的敏感能力时，宿主提供本次运行允许、授权并记住、暂不允许；暂不允许或超时不写永久 deny，持续拒绝由用户在权限设置中选择。私有存储、UI、设置、主题等基础能力无需声明或通用授权；原生文件选择仍由用户确认目标。MCP 非交互调用不代弹授权框。见[权限说明](permissions.md)与[MCP](mcp.md)。
