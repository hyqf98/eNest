# 自由面板与桌面组件

自由面板把插件专门实现的信息卡片放进置顶透明的桌面区域，供用户组合常驻组件。它是宿主的原生容器能力，不是新的插件类型，也不向插件开放任意桌面窗口控制。**`views.layouts` 包含 `panel` 是小组件的能力开关**：只有显式声明并实现组件布局的插件才出现在「添加组件」中，也才允许拖入；未声明的插件仅保留普通窗口入口，不套用完整工作台作为兼容视图。

用户在「设置 → 主题 → 自由面板」启用，默认关闭；由可信宿主入口或配置的快捷键框选区域，再添加插件。区域选择只读取显示器几何和鼠标，不截屏、不录制，也不因此向组件授予屏幕权限。

当前产品是浮动面板，不是操作系统桌面层：macOS 上使用置顶窗口并可显示在其它工作区及全屏应用上方。面板空白区用于移动与右键菜单，即使底板完全透明也不会自动点击穿透。不要将这些行为描述为 macOS 原生桌面小组件。

## 插件如何适配

- 插件保留 `window.enest`。同一 View 从 Tab 或独立窗口移入面板，不复制运行实例，不重放启动业务。
- 在 manifest 声明 `views.layouts` 含 `panel` 后，面板选择该布局；实际布局变化时收到 `onModeChange('panel')`，渲染专用组件视图（时钟、服务器资源、文稿摘要等）。冷启动先读 `getLaunchMode()`，不能只等变更事件。不要只添加声明而仍返回完整工作台；取消支持时从 `layouts` 移除 `panel` 即可，无需再维护另一个布尔开关。
- 组件视图内仍须响应式：用户会自由拉伸组件，200×200 与 400×400 的时钟都应是表盘。使用 `ResizeObserver` 与实际内容区做布局；不要按窗口外框、固定主窗尺寸或屏幕像素计算编辑器大小。组件外框含宿主边缘，插件得到的是内缩后的内容区。
- 优先减少内容，而不是让整张卡片滚动。窄/矮时只保留核心数值或一项摘要，宽/高时再增加少量行；必要的 Grid/Flex 子项设置 `min-width: 0`、`min-height: 0`。不要用 CSS 缩放完整编辑器、终端、表格或 Canvas 来冒充组件。
- 通过 `enest.theme.getAppearance/onAppearanceChange` 消费当前外观，按[UI 标准](ui-standard.md)处理透明底、字体与动画档位；自己的业务状态不能随主题变化重建。
- 移入/移出面板不重载页面：`onModeChange(mode)` 只通知布局的实际变化，业务状态保持；容器尺寸变化以浏览器布局事件为准。同一布局可能运行在不同原生容器，不能把 mode 当作窗口 ID 或挂载位置。

面板组件是常驻呈现，普通空闲三分钟和六实例 LRU 策略不会因它失焦而回收。不要再创建永久活动租约来保活；显式关闭、禁用、卸载和退出仍会释放实例。

常驻策略按原生挂载位置生效，不按 `mode=panel` 字符串判断：真正挂在自由面板内的插件 View 与面板 chrome 关闭 Chromium 后台节流，切换到其它软件不发送退出事件，也不因此暂停组件；移回普通容器后恢复普通页面节流策略。这不是后台权限或系统唤醒锁，不能承诺系统睡眠、进程崩溃后仍持续运行。原生遮挡、失焦后的绘制和平台材质仍须在目标系统验收。

### 一个业务模型，三种呈现

以下配置声明组件布局并允许透出面板底板。`ui.background` 是该插件所有布局共用的原生底色配置，不是仅 panel 生效：

```json
{
  "views": {
    "layouts": ["quick", "shell", "panel"],
    "default": "shell",
    "panel": { "size": { "width": 240, "height": 240 } }
  },
  "ui": { "chrome": "none", "themeAware": true, "background": "transparent" }
}
```

布局只替换呈现，不重复创建业务 store、网络连接或后台计划。面板视图保留核心信息和最多两个主要动作（包括展开）；设置、完整历史和复杂编辑放在主窗。`ui.openInShell()` 移交当前实例，不应先关闭再启动一个新实例。冷启动组件不应为读取摘要创建隐藏编辑器或终端；从工作台迁入时则应保留其未提交文稿、编辑器模型或现有会话，而不是靠重连恢复。

使用官方 kit 时，它会同步根节点 `data-mode`，`kit.mode` 与 `kit.onMode` 均支持三个值：

```js
import '@enest/plugin-kit/style.css'
import '@enest/plugin-kit/widget.css'
import PluginKit from '@enest/plugin-kit'

const kit = PluginKit.create()
const off = kit.onMode(mode => renderLayout(mode, sharedModel))
renderLayout(kit.mode, sharedModel)
enest.onDestroy(() => { off(); kit.destroy() })
```

`sharedModel` 与 `renderLayout` 由插件实现；`renderLayout` 不能重建业务运行域。不使用 kit 也可以直接订阅 `enest.onModeChange`，随后读取 `enest.getLaunchMode()` 完成首屏。

`@enest/plugin-kit/widget.css` 是**可选**的内容样式，不是额外窗口 API。显式使用 `.pk-widget` 才应用半透明表面；可组合 `.pk-widget-heading/title/content/value/caption/actions/empty`，或完全自绘。颜色、字体、圆角读取主题变量，减少透明效果或高对比偏好下降级为实色。它不获取屏幕像素，不提供桌面毛玻璃，不为插件创建拖动区。

```css
html, body, #app { width: 100%; height: 100%; margin: 0; }
html, body { background: transparent !important; }
#app { background: var(--bg); }
:root[data-mode="panel"] #app { background: transparent; }
```

把组件内容放入 `<section class="pk-widget">`，不要同时给 `#app` 留不透明背景。Quick / shell 仍由自己的根内容区绘制 `var(--bg)`，从而避免全局透明配置改变完整工作台的可读性。通用 `.quick-only`、`.shell-only`、`.panel-only` 仅控制呈现，不创建或销毁运行实例。

官方参考实现为插件仓 `plugins/pomodoro`：`App` 共用计时控制器、快照和操作，`PanelView` 只接收渲染数据；组件视图显示倒计时、今日次数、开始/暂停与展开，不另建后台计时器。示例源码不等同各平台原生效果验收。

其它场景可参考插件仓中各插件的 `src/jsx/PanelView.jsx`，不要把不同业务套进同一种工作台缩略图：

| 场景 | 插件参考 | 组件范围 |
|---|---|---|
| 时间与计时 | `timestamp`、`pomodoro` | 实时时钟/有限世界时区，或当前阶段倒计时；不放转换器和历史管理 |
| 文稿与笔记 | `markdown`、`sticky-notes` | 当前文稿或笔记摘录；编辑、完整 Markdown 渲染与资源管理在主窗 |
| 任务与常用片段 | `todos`、`clipboard` | 下一项待办及少量队列，或主动保存的暂存片段；不展示最新剪贴板历史 |
| 本地文件 | `anything` | 文件名检索与有限结果，沿用已有授权与打开动作；不放预览工作台 |
| 远程资源 | `ssh` | 当前已连接会话的真实资源快照；无连接时引导到主窗，不自动另开连接/采样器 |
| 本机进程 | `sysguard` | 进程 CPU 合计、驻留内存合计与有限 Top 进程；不冒充系统总使用率 |
| 分享状态 | `lan-share` | 已创建分享的取件码、到期时间、下载数与复制链接；不自动开始分享 |
| 轻计算 | `calculator` | 单表达式与实时结果；科学键盘、变量和历史管理留在主窗 |

组件背景、排版、图像与图表由插件决定；主题只提供统一颜色、字体、圆角等语义，不强制统一业务布局。类似天气卡的图文背景和大号数值可以由插件自绘，但天气数据、图像素材和信息取舍仍属于插件，而不是宿主注入的功能。

### 按宽高调整内容预算

可选的 `@enest/plugin-kit/widget` 提供框架无关的尺寸订阅，与 widget CSS 分开使用：

```js
import { observeWidgetSize } from '@enest/plugin-kit/widget'

const stop = observeWidgetSize(widgetElement, ({ width, height, compact, rowLimit }) => {
  // 插件决定呈现内容；rowLimit 为 0 时只显示标题/总数，不硬塞一行。
  renderSummary({ width, height, compact, items: model.items.slice(0, rowLimit) })
}, { reservedHeight: 104, rowHeight: 32, maxRows: 6 })
enest.onDestroy(stop)
```

订阅立即返回一次尺寸，此后只在元素 `clientWidth/clientHeight` 改变时回调；返回函数断开 `ResizeObserver`，切换卸载视图时也应调用。`compact` 的默认判断为宽度小于 260 或高度小于 180，`wide` 为宽度至少 360；这些只是可选呈现提示，不是原生尺寸族或宿主能力。`rowLimit` 按可用高度计算、最低为 0，插件可调整预留高度、行高与最多行数，或完全使用自己的 CSS 媒体/容器查询。不要用这个工具逐帧回传原生窗口尺寸。

小组件需要真实的加载、空内容、离线与错误态。监控只能展示已有连接的实际采样，不显示伪造的百分比；剪贴板等隐私内容应明确选择展示范围。只有复杂工作台、没有合理摘要场景的插件无需支持 panel。

## 用户操作与资源生命周期

| 用户操作 | 运行时与布局行为 |
|---|---|
| 把插件移入面板 | 先验证显式支持 panel，再沿用当前 View 与运行域，由宿主记录组件位置与层叠顺序 |
| 从普通 Quick 搜索（未指定显式目标）或宿主普通打开（`ShellOpenPlugin`）再次打开已有面板组件 | 聚焦原组件并交付新的启动载荷，不抽离面板 |
| 从 Workspace 目录、详情或首页搜索打开已有面板组件 | 显式请求 shell，由统一启动器按已适配布局或 default 解析到主窗 / Quick，并将原实例移出面板；与上一行不是同一入口 |
| 从面板移回主窗 | 移交原 View，保留当前业务状态；从该面板布局移除组件 |
| 移除组件 | 走正常有界关闭链路并从布局删除；与保留实例的「移回主窗」不同 |
| 关闭整块面板 | 每个插件走正常有界关闭链路，然后销毁面板；删除这块布局记录 |
| 关闭自由面板功能 | 释放面板与插件，保留布局；再次启用时恢复 |
| 退出应用 | 先结束拖动并保留完整布局，再释放插件；异步关闭不能把布局误写为空 |
| 启动或重新启用 | 先建面板和占位，再最多两个并发挂载组件；启动失败保留错误与重试入口 |
| 旧布局包含未适配插件，或新版本撤回 panel 支持 | 不启动兼容工作台；保留宿主占位与原矩形，可在主窗打开或显式移除，不删除插件业务数据 |

布局属于宿主 `panels` 数据，与普通 Tab/独立窗口会话历史分开。插件不读写该段，也不能通过普通私有存储控制面板位置。业务草稿仍由插件按[存储标准](storage.md)提交；宿主记住窗口位置不等于已经保存编辑器内容。

关闭会等待所有组件的有界回收结果，不能把“视图已经摘除”当作“资源已释放”。单个组件或面板关闭失败、且面板原生表面仍可用时，保留资源回收失败占位，可重试释放；不会把仍待回收的组件直接重新启动。关闭功能时仍收起面板并保留布局，但会通过统一通知报告未确认释放的资源，并将失败返回调用方。旧占位不能关闭用户后来在其它容器重新打开的新实例。

`views.default` 是普通启动未适配请求的回退，不是强制启动布局；默认 panel 的插件仍优先使用已适配的 quick/shell 请求。只有请求未适配且最终回退 panel 时，统一启动器才在主窗承载 panel，不自动创建自由面板。宿主 `ShellOpenPlugin` 新开实例则始终保留主窗位置，即使回退 quick。固定到主窗保留指定位置；拖入面板必须显式支持 panel，不走 default 回退。入口决策见[UI 集成标准](ui-standard.md#三种布局与挂载位置)。

恢复任务绑定当前面板与组件代次。关闭、禁用或卸载会取消旧挂载；重新启用后的新实例不能被旧任务关闭，失败的窗口创建也不能被当作用户删除布局。插件不应在自身初始化中再次创建或恢复另一套面板。

## 外观、拖动与多屏

主题语义颜色、字体、圆角和动画档位来自宿主的权威外观快照。**面板底板的不透明度与原生材质是独立的宿主容器偏好**，不会自动随第三方主题覆盖；材质支持 `none/blur/system`，具体原生效果由操作系统决定。主题也不能接管插件权限弹窗、组件归属或窗口几何。

原生材质作用在**整块面板窗口**，不是逐张组件卡片。opacity 只控制底板色调和描边；`blur/system + 0%` 仍保留系统材质，`none + 0%` 才是无底板材质与色调。插件可用语义颜色自绘半透明内容，但 CSS `backdrop-filter` 不能跨 WebContentsView 采样真实桌面；当前没有逐卡片桌面模糊、壁纸自动取色或标准小/中/大尺寸族。

新配置默认使用 `none + 0%`，只显示插件自己的外观，不再给组件叠加常驻边框或阴影。已有保存的底板设置不自动覆盖；在「设置 → 主题 → 自由面板」点击「设为透明」，可一次关闭底板色调与原生材质。透明只针对宿主容器，不降低插件内容的不透明度，也不代表鼠标穿透：组件外沿的透明热区仍用于拖动、缩放和右键操作。

拖动、缩放、吸附与对齐线由宿主主进程处理，组件不需要高频发送坐标。直接拖动组件边缘即可移动，拖动四角即可缩放；不需要切换编辑模式，也没有需要点击的「完成编辑」按钮或常驻角点装饰。平时显示真实插件内容，按钮、输入和滚动保持可交互；宿主的边缘与角部命中区域不要求插件自绘拖动控件。

可信 chrome 只发送手势开始、结束和低频存活心跳；主进程独立读取系统光标并更新原生几何，不依赖 renderer 的逐帧 `pointermove/RAF → IPC`。静止位置不重复布局，几何与吸附线反馈按变化合并限频；松手提交最终位置，取消恢复起始位置。原生窗口失焦/隐藏立即取消当前手势；chrome 崩溃、关闭或心跳超时也会回收拖动调度并恢复视图，旧手势消息不能结束新的手势。

拖动经过位移阈值后开始。仅在实际拖动、缩放或面板菜单打开期间，宿主短暂隐藏插件原生视图，并使用组件页面的一次性有界预览，避免 WebContentsView 截获指针或遮住菜单。松手后自动恢复真实内容并保存布局，菜单关闭后自动恢复交互；Esc 或指针取消也会结束当前手势。这不是关闭业务实例，不需要另行确认。预览不是实时内容，超出捕获预算或失败时显示占位；插件无需复制 UI 或重建实例，也拿不到其它组件的预览数据。不要给面板叠加第二层原生拖动，或用 `-webkit-app-region: drag` 代替需要右键交互的区域。

当前容器最多 8 块面板、每面板 24 个组件；面板最小 320×240 DIP，组件外框最小 200×140 DIP。吸附参考同面板组件和边界，阈值为 6 DIP；初始落位按 8 DIP 网格寻找空位。缩放只吸附正在移动的边，不越过最小尺寸。这些是宿主几何约束，不是插件应硬编码的内容区尺寸。声明了 `views.panel.size` 的组件按声明尺寸初始落位（受上述约束钳制），此后以用户拉伸和保存的矩形为准。当前内容区四周各内缩 4 DIP，例如 240×240 外框提供约 232×232 的视口；仍应读取实际 viewport，不把这组数值当作永久布局承诺。插件的 `ui.resize/setHeight` 不控制面板几何。

窗口位置使用 DIP，并保存显示器标识；负坐标在多屏布局中合法。恢复时优先定位仍存在的显示器，否则按当前屏幕几何重新选择并约束到工作区；显示器移除或缩放变化也会重算可见位置。插件内部 Canvas 的绘制分辨率仍需按实际 `devicePixelRatio` 调整，不能把物理像素直接当作宿主窗口坐标。

## 安全与集成边界

`enestPanel`、`PanelSurfaceApi` 和区域选择桥仅供宿主可信表面使用，不属于普通 `window.enest` API。插件不能借面板身份发送壳 IPC、操纵其它组件或读取完整设置。宿主仍逐次校验窗口角色、主 frame、组件归属和运行代次；跨窗口迁移不增加权限。

发布面向桌面组件的插件时，应在目标系统检查小内容区、拖动后的布局、低动画档、重启恢复、关闭保存，以及不同缩放率与显示器拔插。静态类型和构建检查不证明原生拖动、材质或混合 DPI 的实际表现。相关契约见[设置与窗口](settings-and-windows.md)、[生命周期](lifecycle.md)和[主题规范](themes.md)。
