可组合的桌面工作台

eNest 不是又一个「万能启动器」。它是一层可扩展的桌面壳子： 用插件组合效率、开发与内部工具，进程隔离、权限可控、数据本地优先。

Lifecycle

插件生命周期

插件在壳子中以原生 WebContentsView 存在：打开 → 可见/切换 → 重载 → 关闭销毁。无 LRU 保活，关 Tab 即回收，内存可预期。

未安装 → 已安装 → 运行中（Tab） ⇄ 激活 / 隐藏 → 重载 → 关闭 · 销毁

打开（Open）

解析安装路径 → 创建隔离 session → 注册 enest://plugin/{id} → 注入 pluginPreload → 加载入口 URL → 推送 plugins-changed。

关闭（Close）

关闭 Tab 立即 webContents.close() 并移除 View；关窗口则 destroyAll()。插件应在 pagehide 自行 flush 状态。

切换 Tab 仅改 setVisible，不销毁不可见页；窗口 resize 时由 PluginHost 重算所有插件 bounds。 细节见 生命周期文档。
Isolation

进程与会话隔离

每个插件是独立的渲染进程与持久化 partition，Cookie、localStorage、缓存互不串扰。

会话 partition

打开时使用 session.fromPartition('persist:plugin-' + id)，协议映射仅指向该插件根目录，路径穿越会被拦截。

  • 独立 Cookie / 存储 / 缓存
  • CSP 约束下的本地资源加载
  • 卸载时按版本策略清理数据

窗口层级

Shell UI 铺满窗口；Plugin View 叠在内容区（标题栏 + 插件条之下），保证壳子控件始终可点、插件全幅可交互。

  • 标题栏 / 插件条不被原生层遮挡
  • 多 Tab 并行，各自 View 独立布局
  • 关窗统一销毁，无残留进程

每个 Tab 一座「巢」

不是 iframe 拼盘，也不是单体工具箱。eNest 把每个插件提升为独立渲染进程： 崩溃、内存、会话数据彼此隔离，关闭即回收。

需要并行工作时多开 Tab；需要专注时只留一个。工作台随任务组合，而不是被固定布局锁死。

UI standard

UI 集成标准

插件可用任意前端技术绘制界面。壳子通过 plugin.json 的 ui 段统一管理 chrome、主题注入与背景透明。

Chrome 模式

  • default：标准 48px 插件条，显示名称与协议路径
  • minimal：细条 28px，最大化纵向空间
  • none：无条全幅，适合看板、游戏、可视化

主题与背景

  • themeAware：加载后注入 CSS Token，切换时推送事件
  • background: transparent：可透出壳子壁纸
  • preferredColorScheme：light / dark / auto

plugin.json ui 示例

{
  "ui": {
    "chrome": "default",
    "themeAware": true,
    "background": "opaque",
    "preferredColorScheme": "auto"
  }
}
完整字段与 Token 列表见 UI 集成标准。

主题即基础设施

壳子把颜色、圆角、背景等 Token 推给插件；主题包可动态注册（enest.theme.register）， 切换后经 theme-aware 事件即时刷新。

插件无需嵌入壳子 DOM，也无需重复实现深浅色逻辑——声明 themeAware 即可。

Why eNest

和「浏览器标签」或「单体工具箱」的差别

eNest 在桌面壳层做组合：每个插件是真正的独立 Web 应用，而不是 iframe 拼盘；也不是把所有功能焊死在一个安装包里。

  • 进程级隔离，故障与内存不互相拖累
  • 权限白名单，插件只能调用声明过的 API
  • 本地优先数据，适合内网与离线场景
  • 清单驱动安装，便于版本化与分发 .enestplugin
